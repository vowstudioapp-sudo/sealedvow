## What this PR did
Added a schema-layer preprocess helper `emptyStringToUndefined` in `lib/coupleDataValidator.js`. Applied to five optional URL fields. The preprocess coerces `''` (empty string) to `undefined` before Zod's `.optional()` runs, allowing untouched-but-present optional URL inputs to validate cleanly.
## Why this PR was a P0 hotfix
### The bug
During PR-46 E2E validation at 00:05:28 IST 12 May 2026, a real Razorpay transaction failed in a specific and dangerous shape:
- Frontend submitted couple data with `musicUrl: ''` (empty string, default for untouched optional URL input)
- Razorpay captured the payment (₹249, order `order_So9q9GgBiRYea6`)
- verify-payment called `validateCoupleData`
- Zod's `.refine(isValidUrl).optional()` rejected `''` because:
  - `.optional()` permits **absence** (undefined), not **presence-with-empty-string**
  - Empty string is present, so `.refine(isValidUrl)` runs
  - `isValidUrl('')` returns false
  - Schema returns "Invalid input"
- verify-payment returned HTTP 400
- Frontend showed user-facing error "Invalid session data."
- **Result: payment captured, no fulfillment, no email, no share link.**
### Why P0
This was the worst possible failure shape: money charged with no product delivered. Any user encountering this would see only "Invalid session data" with no path forward. Their card would be debited. Their letter would be lost.
Discovered before scale traffic hit, in the observation window of a controlled test. Without the observation window, this bug would have shipped to real users.
## Root cause
**Architectural contract drift between frontend and backend semantics.**
| Layer | Empty optional URL semantics |
|---|---|
| Frontend (HTML/React inputs) | `''` (empty string) for untouched optional input |
| Backend (Zod `.optional()`) | `undefined` (absent) for optional fields |
The frontend emits a `''` for every uncontrolled optional input by browser default. The Zod schema interprets `.optional()` to mean "either undefined or a valid value." The semantic gap was invisible until both layers exercised an optional URL field in the same path.
The deeper architectural truth: this is a **class** of bug, not a single instance. Anywhere frontend defaults to `''` and backend uses `.optional()`, the same gap exists. Five URL fields surfaced in this PR. Other gaps may exist in non-URL fields or in nested structures.
## The fix
### Helper
```javascript
const emptyStringToUndefined = (val) => (val === '' ? undefined : val);
```
Applied via Zod `.preprocess()` at the schema boundary.
### Fields touched
Five optional URL fields in `lib/coupleDataValidator.js`:
1. `userImageUrl`
2. `aiImageUrl`
3. `musicUrl`
4. `giftLink`
5. `manualMapLink`
### Fields deliberately NOT touched
1. **`futureImages[]`** — array case, not a single value. The fix shape would be "filter not coerce" (drop empty entries from array), which is a different operation. Deferred.
2. **Required-nested URLs** — fields where empty string is genuinely invalid (no `.optional()`). Leaving Zod's strict rejection intact is correct here.
### Why schema-boundary normalization, not other shapes
Three alternatives considered, all rejected:
1. **Fix in frontend** (don't emit `''`). Rejected: doesn't fix the architectural class; new frontend code in the future would re-introduce the gap.
2. **Fix in verify-payment** (preprocess before calling validator). Rejected: leaks the bug into every caller of the validator. Founder-code path shares the validator at `api/verify-payment.js:337` and would need the same fix.
3. **Change `.optional()` to `.optional().or(z.literal(''))`** at each field. Rejected: more verbose, less reusable, and tangles the schema with frontend-semantic accommodation.
Schema-boundary preprocess via `emptyStringToUndefined` is the cleanest fix: it accommodates frontend reality at exactly the layer where the contract is interpreted, without polluting callers or duplicating logic.

## Discoveries during this PR
1. **"Failed CLOSED, not failing DIRTY" worked correctly.** The validator did its job: it rejected the malformed input before any corrupted state was written to RTDB. No ghost session, no orphan letter, no half-fulfilled state. The cost was a stuck payment (resolved via manual refund). The alternative — silent acceptance of `''` and writing a session with broken `musicUrl` — would have been materially worse.
2. **Architectural contract drift is a class.** Expect more instances. Future audit recommended: grep for `.optional()` across all Zod schemas, cross-reference against frontend defaults, identify gaps.
3. **Observation window doctrine validated.** The post-deploy E2E test caught this within 5 minutes of merge. Without the observation window, the bug would have shipped to whatever scale traffic arrived next.
4. **Manual refund as operational closure.** The failed transaction (order `order_So9q9GgBiRYea6`) required a Razorpay dashboard refund. Captured in the operational closure log for 12 May 2026 morning. This strengthens the case for PR-48 (auto-refund safety net) — the next-occurrence response should not require human intervention.
